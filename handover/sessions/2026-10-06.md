## Round 4 — the deep dive, `tools/charts-fast.py` + `scripts/build-charts-intraday.js` + the workflow
Read from the code, two causes of "too long" and one of "can't get HEX":
- **Every intraday range (24H / 7D / 14D) was drawn ONLY from live GeckoTerminal calls** — one gated call per token, 2.2 s apart,
  a refusal pausing every call 4 s then 8 s, then a 45 s circuit (the 2026-10-05 back-off, correct but slow by design). Eight
  tokens = 20–40 s with an empty canvas; the majors' intraday went to the keyless public CoinGecko endpoint, as 429-prone.
- **A range or token click while a load was in flight QUEUED behind it** — `go()` returned with `pendingGo=true`, so the new range
  appeared only after the old load's last gated call. The abort machinery existed but was never used by a new load.
- **"HEX unavailable"**: a refused token's last resorts were the daily file (7D / 14D only — his "HEX daily candles") or
  DexScreener's two points; on 24H neither exists, so a refusal was "unavailable".
Fix, three parts:
1. **A prebuilt INTRADAY file.** `scripts/build-charts-intraday.js` (CoinGecko Pro key, server-side, the daily builder's twin —
   2 s pacing, carry-forward per token-tier, never overwrites a good file with nothing) writes `data/charts-intraday.json`:
   14 d of 1-hour closes (`hourly`, the 7D / 14D tier) and 24 h of 15-min closes (`minute`, 24H) for all 8 PulseChain tokens
   (the page's own pool first — the same series the browser tops up — then the token endpoint) and the 5 majors (market_chart,
   days=14 / days=1). Prices to 7 significant digits; ~170 KB. New HOURLY step `charts-intraday` in `data-pipeline.yml`
   (gate list, step, commit list, report), `only=charts-intraday` reruns it alone.
   In charts.html, **phase 0.5 of `go()`**: on an intraday tier the file is read ONCE per 5-min slot (raw CDN cache) and every
   token with a series paints AT ONCE (clipped to the range). A token whose file series reaches within 1.5 candles of now is
   cached fresh and needs no live call; one topped up in the last 3 min (`_liveTried`) stays as painted; the rest keep their
   place in the live phase, whose answer is MERGED onto the file's series (`mergeSeries`, one point per candle, live wins) and
   cached. A refused top-up leaves the file's full line — the status line reads an honest amber "as of <newest>" past 2 h, and
   "updating" with a spinner while a painted chart is being topped up (`_statusUpdating`) instead of "Loading… 2/5" over a
   drawn chart. Missing or > 36 h-old file → everything behaves exactly as before (verified).
2. **A new load supersedes the one in flight**: `go()` no longer queues; it aborts the previous controller, bumps the generation,
   and the old cycle's `finally` tidies the overlay / spinner / watchdog only if it is still the newest. `progress()` is
   generation-guarded.
3. **The GeckoTerminal gate gives no 2.2 s slot to an aborted call** (`gtGate(signal)`) — a superseded load's queued calls no
   longer delay the new one.
Refresh clears the file memo + `_liveTried` and goes live again.

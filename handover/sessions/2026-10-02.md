# 2026-10-02 — LP Pairs alignment (round 22)

Shaka opened with a screenshot of the v2 LP Pairs table: "we need better visual alignment from the headers in this lp pairs
section to the data under it … some is left justified, some centered". Then the band's three tiles: "look at how the title and
numbers are laid out in these three boxes. need consistency."

## What was wrong

- **Table:** three alignment rules across eight columns. Volume / Value Gen / Liquidity were left-aligned text under
  left-aligned headings, Price 24h / Txns / Vol-Liq were centred (`.c-mid`), Actions was right. The curve column had no
  heading, so VOLUME 24H looked like it floated over nothing, and the VALUE GEN / LIQUIDITY headings (110 px column, heading +
  arrows fill it) ran together.
- **Tiles:** `.p2-lphk` was `grid-template-columns:auto auto; justify-content:space-between` — the first column is sized by
  its content, so the centred label moved with the figure's width ($66,473 vs $2,180,115 put the label at different x's).

## Built (index.html, v2 only — `p2-lp*` CSS + the v2 heading row; classic proven byte-identical with `probes/lp-dom.js`)

- `.p2-lpth>div{text-align:center}`; `.c-l` (Pair) left; `.c-dim` = the curve column's "7D" heading (`<div className="c-sp
  c-dim" aria-hidden>`, so it leaves with the column under 1120). The `#` and Actions headings lost their inline styles.
- `.p2-lpr>div{text-align:center}`; `.p2-lpnm` left. `.p2-lpsp` padding `0 10px`, svg `margin:0 auto` (the curve used to hug
  the volume figure — centred under "7D" now). `.p2-lpac{justify-content:center}`. `.c-mid` stays (now redundant, harmless).
- `.p2-lphk{grid-template-columns:1fr auto}`; `.l` / `.v` `justify-self:start;text-align:left`.
- Checked 1440 PTGC, 1200 UFO, 1024, 900 (`probes/lp-fit.js`: actions inside the panel, no page scroll). Render
  `renders/lp-align-built-1440.png`.
- Applied with one python replace script run on BOTH copies (cloud clone for the harness, the Mac for the commit) — same
  sha256 after (`a6ab3092…`). Harness in the cloud workspace again (fresh clone, `npm install`,
  `CHROME=/opt/pw-browsers/chromium-1194/chrome-linux/chrome` worked this time).

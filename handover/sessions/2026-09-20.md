## a39 — burn-summary's UFO section (the RETIRED contract) leaked into two fallbacks

**Cold-cache market cap.** `mcapFromPrice` subtracted `burnHistoryCache[cfg.name].totalBurned`
by token NAME. burn-summary's UFO section is scanned from `UFO_ADDRESS`
`0x456548…` (fetch-burn-history.js:31) — the retired contract — so on a first visit during a
DexScreener outage UFO's mcap was `(999.99B − 209.98B) × price`: 79% of the starting supply,
about 12% under the real circulating figure, printed as a plain number. New order:

1. **this session's own on-chain read** — `fetchBurn` now remembers `{burned,supply}` per
   address in `liveBurnedCache`, which is `totalSupply()` minus the burn address's balance:
   the right answer, no file involved;
2. the file, but only when that section carries an `address` stamp matching the token being
   priced (the generator now writes `address:` on the PTGC and UFO sections, and
   `data/burn-summary.json` carries both stamps already so the deploy is correct before the
   next pipeline run — same move as a36's `treasury-recent.json`). A generator repointed at
   the live UFO contract therefore starts subtracting again on its own;
3. the starting supply — the documented overstatement — rather than someone else's burn.

**The "PTGC burned by UFO" v1 base.** burn-summary also carries its own `PTGCbyUFO`
(4.14 B): *PTGC burns sent from the PTGC/WPLS pair* — PTGC's own buy-and-burn leg, nothing to
do with UFO. It only ever looked right because `ufo-ptgc-burns.json` overwrote the field two
lines later; when that 300 KB fetch failed, the headline silently became 4.14 B + v2. The
reader now clears the field on load, so a failed second fetch leaves the v1 base genuinely
unknown and a17's `oldMissing` labels it. The generator also stamps the field with a `source`
line saying what it actually measures.

## a42 — tier math undercounted at exact thresholds

`0.3/0.1` is `2.9999999999999996`, so `Math.floor` rendered one creature too few of the top
tier and then a tail of ×9s — `getBurnC(0.3,'Squid')` gave "2 sharks + 9 dolphins + 9 squids".
One helper now: `creatureCount(value,unit)`, which treats a quotient within a **relative**
1e-9 of a whole number as that number (relative, because the quotient can be in the millions)
and otherwise floors. Used by `getBurnC`, `getHighestCreatureWithCount`,
`getCreatureForPtgc` — which no longer carries its own copy of the loop, it delegates — and
`getBurnCreaturesTwitter`, whose `%` remainders had the same class of error in token units.

## a67 — the five numeric consistency nits

- **`fmtAbbr`** picks its unit AFTER the 2-dp rounding: 999,999 is "1.00M", not "1000.00K"
  (same band at every magnitude). 999.995e3 is the smallest number that rounds up, so that is
  where each unit starts. "1000.00T" stays — there is no higher unit.
- **`findBlockAtTime`** widened on a failed HIGH edge probe but trusted a failed LOW one,
  converging on a boundary later than the real one — every window silently short. Now widens
  on both, which is what the mid-probes' `if(!t)return null` invariant always implied.
- **The two share-card tier tables** (CombinedLeaguesModal, TierInfoModal) derive from
  `BURN_C` instead of being a second and third copy of the eight percentages. `tierFraction()`
  converts percent → fraction through `toPrecision(15)`, because `0.00001/100` is one ulp off
  the `1e-7` the literals had; with it the rendered numbers are byte-identical. Shell is
  `p:0` in BURN_C (the floor), but a card that prints a token amount per row needs a number
  for it, so its display threshold is named once as `SHELL_CARD_PCT`.
- **portfolio.html's Shell** is now the floor (`pct:0`) as BURN_C has it: a wallet holding
  2,000 PTGC is a Shell working toward Shrimp, where it used to read "below 🐚 Shell" while
  the dashboard counted it as a Shell.
- **calculators.html's UFO ATH** is index.html's rule verbatim
  (`coingeckoDataCache?.[token]?.ath||ATH_PRICES[token]||0`); `ufoNewTokenAthCache`, the
  GeckoTerminal daily-high cache that would have made the two headers disagree the first day
  a wick beat $0.000113, is gone along with the `isMain` / `mainPairAddr` code that fed it.

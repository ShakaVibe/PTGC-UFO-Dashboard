## The "3.8h ago" that looked like 8.8h — resolved, no bug

A first probe fetched `https://ptgc-ufo.com/data/value-generated.json` and found
`meta.generatedAt` 06:12:34Z — 8.9 h old — while the dashboard said "as of 3.8h ago".
The label is right and the probe was wrong: the app reads
`raw.githubusercontent.com/.../main/data/value-generated.json` (`VALUE_GEN_URL`, and
the same for burn-summary, dao-buys, coingecko, charts, ledger), which had a ~11:20Z
file. `deploy.yml` says so explicitly: data commits carry `[skip ci]` and are pushed
with `GITHUB_TOKEN`, so they never re-deploy Pages, and they don't need to.

**Filed (cleanup, unnumbered — for the a39+ batch):** the copies under
`ptgc-ufo.com/data/*.json` are still published in `_site` and are frozen at the last
code deploy (06:12Z today, while the repo was at 11:20Z). Nothing on the site reads
them — every reader is a raw-GitHub URL — so they are dead weight in the 18 MB
artifact and a trap for any future relative `/data/…` fetch, which would silently get
deploy-old numbers. Either drop `data/` from the `_site` allow-list (a38's list) or
keep it and never fetch it relatively.

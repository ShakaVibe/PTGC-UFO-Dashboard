# 2026-09-17 — Audit II honest-failure pass: a14, a15, a17, a18, a19, a20, a21, a23

One pattern across the eight remaining items in a14–a24 (a16, a22, a24 were done on the 16th):
a value that could not be read is `null` all the way through, and every surface prints `null` as
"—" (`fmt`/`fmtUSD`/`fmtAbbr` already did). Nothing new is calculated; only the "unknown → 0"
coercions were removed and the places that multiplied by an absent price now say so. Verified in
the harness (cloud workspace, the local VM has no Chromium): normal / `RPC_DOWN=1` / `DS_DOWN=1` /
both, at 1280–1440 px and 375 px, Home → PTGC → UFO → KPI (+ Add UFO) → Socials (all five cards)
→ Live Feed (UFO). No console errors beyond the expected 503s / "all 3 endpoints failed".

## What changed (index.html, ~380 lines net)

- **a14 — DexScreener outage.** `fetchDex`'s main return now knows whether any pair came from
  DexScreener (`_dsLive`). If none did (all built from the chain), `vol` / `buys` / `sells` /
  `change` are `null` and the object carries `_fromChain:true`; chain-built pairs get a real
  `liq` from reserves × the price we ended up with (they were priced with `tokenPrice=0`
  before). The no-pairs fallback returns `null` for all six fields. Consumers: one
  `changeKnown` / `changeTxt` / `changeCls` trio in the Dashboard feeds the three header/tile
  24h-change lines ("—" instead of "↑ 0.00%"), LIQ / MCAP, Tokens in LP (`tokensInLPKnown`),
  Txns 24H (dash, split hidden), the Volume modal (24H tile + comparisons), the Value Generated
  24h volume (`v24` null → "Data unavailable"), and the Price-with-Cores card's ▲ badge.
- **a15 — burn USD + allocation.** `fetchStakingData` returns `null` when either `eth_call` has
  no result (and from its catch); `stakingData` is seeded / reset with `null`. The allocation
  rows carry `known` flags (burn: `burn.supply>0`; In LP: `data.tokensInLP!=null`; Staked /
  Lock: `stakingData`; Held: all three); unknown rows are `{value:null,tokens:null}` → "—" in
  the panel legend, the share-card legend and `DonutChart` (which draws the empty ring when any
  slice is null). Circulating Supply dashes with the burn; the burn headline's USD dashes with
  the count or the price (panel + burn card).
- **a17 — PTGC burned by UFO.** `computePtgcBurnedByUfo` returns `pending` (no live-contract
  figure yet → `totalBurned:null`, `burnPct:null`), `failed` (`delivered.ok===false`) and
  `oldMissing` (history file absent). Panel + card: headline "—" (pulsing while reading, tooltip
  says why), USD "—" when pending or `ptgcPrice` is 0 (headline and the four window tiles), % "—";
  amber line under the tiles for "chain read failed" / "old-contract history unavailable — new
  contract only". `getWhaleProgress` / `getBurnC` get `burnPct||0`.
- **a18 — five cards.** New module-level `CardLoadState` (loading / "Couldn't load X — Retry"
  overlay inside the card, so a Download in that state shows the message, not $0). Combined Burn:
  the inline loader is now `loadCombinedBurnOther()` (next to `closeModalAndReturn`) with
  `combinedBurnError`; `fetchBurn` null = error; a burn with `supply 0` is `null` → `TokenBlock`
  prints "—" for total / USD / % / whale multiplier and dashes USD rows when the price is 0.
  RH Cores: `loadOtherTokenPairs()` + `otherPairsStatus` (idle/loading/ok/error), columns with no
  pairs are null → "—" (rows, column total, grand total). Affiliates: `loadAffiliateShare()` +
  `affiliateShareError` (non-2xx / non-JSON count as failures) → error + Retry in the shell.
  Combined Holders: `holdersShareError` + `holdersShareTry` (effect dep) → error + Retry.
  Combined Leagues: price formatters print "—" once loading is over, amber "Price unavailable
  for X — Retry" under the subtitle (`priceTry` re-runs the effect).
- **a19 — KPI compare card.** `otherHolders` seeded `null`, `setOtherHolders(h)` keeps null;
  `priceChange` null → grey "—" badge (card + `TwitterCard`); PLS ratio needs `price>0&&pls>0`;
  LIQ/MC needs `liq!=null`; burn USD needs a price; `volumeByPeriod` seeded / reset with nulls so
  VALUE GEN 7D is "—" until the CoinGecko file lands, not "$0". `loadOtherToken` no longer
  auto-switches to X mode when `fetchDex` returned null — the compare view shows a "Couldn't
  load UFO — Retry" card instead.
- **a20 — quickRefresh token guard.** `tokenRef` (next to `closeModalAndReturn`). `quickRefresh`
  captures `t=token` and bails after the awaits when `tokenRef.current!==t`; the `[token]`
  interval effect's cleanup resets `refreshBusyRef`. Same guard in `loadCombinedBurnOther` and
  `loadOtherTokenPairs`.
- **a21 — partner prices.** `plsxPrice` / `wethPrice` seeded `null`, setters guarded `p>0` like
  PTGC's. `vgPriceMap` returns `null` for an unknown price. `computeValueGenBuckets`: a bucket
  with delivered tokens and no price is `null`, `total` is `null` if any bucket is, and
  `missing` names the price keys. `computeValueGen` passes `missing` through (basis
  'delivered'); `valueGenBucketUsd` returns null per bucket instead of nulling the whole model.
  Panel tile maths: `needs(qty,key)` → `usd:null` + `priceMissing`, tile prints "—" with a
  tooltip; headline "—" + amber "PLSX / WETH price unavailable — that bucket shows —" instead of
  the tiles' partial sum; `deliveredUsd` sums `i.usd||0`.
- **a23 — deck estimate.** `deckWindows` for UFO comes from `computeValueGen` (delivered or
  accrued basis only); no window when the read is pending/failed. `seedTotals` never uses
  `data.vol × fee` for UFO; the ready gate does not fall through to the 20 s fallback for UFO
  without a window (pods stay "loading" / "no data", readout "— reading chain" / "— chain read
  failed" via the new `windowState` prop = `deckWindowState`); `poolRank` USD is "…" for UFO until
  the measured figure is in; the initial `win` moves to the longest window that exists.

## Harness

`probes/fetch-fail-all.js` (+ every RPC POST) — run them with `evalfile=` after the page is up,
then open the cards. README has the line. Note `eval=` cannot hold semicolons; use `evalfile=`.

pods and its readout says $0 — identical on the pre-change file; UFO's KPI "7D EST" prints $0 for
the same reason (fee rate 0).

## Evening — a29: one hourly Data Pipeline workflow

**Diagnosis first (the Actions API, public repo, no auth):** every run in the last 100 succeeded,
so nothing was failing — the runs were not being created. `0 */6` jobs started at 04:29 / 11:18 /
16:38 / 21:10 (4–5 h after their cron), the hourly ones about five times a day, `update-metrics`
(48 crons/day) the same five. GitHub delays and drops schedule events for a repo that asks for
too many; this one asked for ~190 a day across nine workflows. So the fix is fewer schedule
events, not different minutes.

**What changed**
- `.github/workflows/data-pipeline.yml` — ONE workflow, cron `7 * * * *`, sequential steps in
  data order (charts → coingecko → value-generated → burn-history → treasury → dao-buys →
  ufo-ptgc-burns → token-allocation → lv-snapshot), one commit per run (explicit file list, the
  same rebase-and-retry push), `concurrency: data-pipeline`, 50-min timeout, Node 22.
  Every script step is `continue-on-error`; a final "Report step failures" step exits 1 if any
  step failed, so the workflow still goes red AFTER the good files landed.
  `workflow_dispatch` inputs: `only=` (comma list of step names — the by-hand run after editing
  a script) and `force=true` (ignore the age gates).
- `scripts/pipeline-gate.mjs` — the steps that used to run every 2 h / 6 h are gated on the AGE
  OF THEIR FILE (`lastUpdated` / `generatedAt` / last snapshot `timestamp`, 15-min tolerance),
  not the clock, so a delayed run never skips a window: charts 2 h; ufo-ptgc-burns,
  token-allocation, lv-snapshot 6 h. Missing / unreadable file → run.
- `scripts/lv-snapshot.js` — the 125-line `capture.js` that lived inline in lv-snapshot.yml,
  moved unchanged.
- Deleted: build-charts-data, build-token-allocation, build-value-generated,
  fetch-coingecko-data, fetch-treasury, fetch-ufo-ptgc-burns, lv-snapshot, update-burn-history
  and **update-metrics** (its `metrics-history.json` is read by nothing on the site and the
  script targets the retired UFO contract — a65; the script and file are still in the repo,
  just no schedule). `deploy.yml` untouched.
- Verified: YAML parses, `actionlint` clean, every `scripts/…` path exists, the `git add`
  pathspec matches every file (dry run), the gate script exercised for age / ONLY / FORCE /
  missing file, the report-step and ONLY shell logic run with fake inputs. Not run on GitHub yet
  — the schedule only exists once the file is on `main`.

**After the push (Shaka):** Actions → "Data Pipeline (hourly)" → Run workflow with

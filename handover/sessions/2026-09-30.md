## What was built

**`HEADER_DESIGN`** (next to `HOME_DESIGN`): `'classic'` today; `'v2'` = the new header. The App
reads it once at boot (`headerDesignBoot`) — the constant wins, else this device's preview flag
(`LS.HDR_PREVIEW`, `grays_hdr_preview_v1`) — and hands `headerDesign` to `Dashboard`, which renders
either `DashHeaderV2` + `KpiTilesV2` or the classic blocks. Nothing else in Dashboard changed; the
v2 components take the same variables the classic JSX reads (`data`, `hdrDaysOld`, `plsRatio`,
`xToATH`, `holdersByPeriod`, `txnChange24h`, …) and call the same setters (`setShowSwap`,
`onSwitch`, `setShowBeam`, `setShowVolumeModal`, `setShowRHModal`, `setShowHoldersSingleModal`).

Module-scope pieces (just above `DashboardSkeleton`), CSS block `h2-*` at the end of the head style:

| Piece | What |
|---|---|
| `DashHeaderV2` | The banner (desktop ≥ 1024 px / phone below — both trees rendered, Tailwind `lg:` toggles them) + the **sticky tab row**. The tab row is a sibling of the banner wrapper, not a child, or `position:sticky` would stop where the wrapper ends. Once the banner scrolls away the row grows a logo · token · price · change line (desktop: left of the tabs; phone: a line above them, like today's slim bar). |
| `KpiTilesV2` | The seven tiles. Values = the classic strip's, same "—" rules. Badges keep their jobs: ⓘ Volume by period, RH → RH Cores modal, ⓘ Holders → `HoldersSingleModal`, % of supply on Tokens in LP. Txns spans the row under 1024 px (as the mock-up). |
| `H2Spark` | Inline SVG, 240×60 viewBox, `preserveAspectRatio=none` + `vectorEffect=non-scaling-stroke`; **null series = a dashed flat line with an aria-label saying the 7-day history is unavailable** — never a placeholder shape. |
| `useH2Series` | The 7-day histories (below). |
| `h2Scale` / `useH2Scale` | One CSS variable `--u` = one *reference pixel*: the mock-up was measured at 2166 px wide, so every size in the CSS is `calc(N*var(--u))`. Desktop `--hsd = clamp(.47, width/2166, 1)` (1024 px is the floor: everything is the mock-up scaled by .47, banner 159 px tall; at 1440 it is .665, banner 223 px; ≥ 2166 it is 1:1). Phone `--hsp = clamp(.9, width/390, 1.3)` — a tablet gets the phone layout, larger. `--u` is rem-based, so a bigger browser font scales the whole header (gotcha 17). |
| `HeaderPreviewGate` + `sha256Hex` + `hdrPreviewRequested` | The hidden switch (below). |

### Sparkline data (Shaka: 7 days, every tile)

| Tile | Source | Notes |
|---|---|---|
| Market Cap | GeckoTerminal hourly candles of the main pair, 168 h (`fetchH2Price7d`) | Same sanity rule as the Home chart: the last candle must sit within 25 % of the price the banner prints, else no line. The live price is appended as the last point. 10-minute cache. |
| Volume 24H | `data/lv-snapshots.json` → `totalVolume` | DexScreener, one row per pipeline run (~5/day). **Fetched only when v2 is on** (`fetchH2Lv`, ~370 KB) — a slimmer file is the obvious follow-up if this ever goes hourly. |
| Liquidity | `data/lv-snapshots.json` → `totalLiquidity` | Same rows. (`liquidity-history.json` is GeckoTerminal's figure — $1.5M vs DexScreener's $1.17M — so the lv file is the one that matches the tile.) |
| Liq / MCap | `liq(t) / (price(t) × circulating)` | price(t) from the candles at each lv timestamp; circulating = `data.mcap / data.price`. Null if either series is. |
| Holders | `data/holder-history.json` via `snapshotsFor` | Daily → ~8 points; the UFO epoch rule applies. |
| Tokens in LP | `data/tokensinlp-history.json` | Already loaded by `load()`. |
| Txns 24H | `data/transaction-history.json` → `total` | Already loaded. Its counts come from GeckoTerminal's trade list (171 vs DexScreener's 733 on the tile) — shape only, like the tile's own change line. |

### The hidden preview switch ("How it goes live", agreed 2026-09-29)

`ptgc-ufo.com/?<word>` → `hdrPreviewRequested` hashes every bare query key (one with no `=`) and,
if one matches `HEADER_PREVIEW_GATE_HASH`, strips it from the URL (`replaceState`, hash and other
params kept) and opens `HeaderPreviewGate`: a plain `<Modal>` with a password box. The password is
hashed and compared with `HEADER_PREVIEW_PASS_HASH`; right → `LS.HDR_PREVIEW = 1`, the header flips
to v2 at once and stays on for that device; wrong → "No." and the field clears. When the flag is on
the same link shows a **Turn off** button. `sha256Hex` uses `crypto.subtle` and falls back to a
plain-JS SHA-256 where there is no secure context (http on a LAN address). Shaka computed the hashes on
the Mac (zsh: `read -rs "s?secret: "; echo; printf '%s' "$s" | shasum -a 256 | cut -c1-64; unset s`
— nothing typed lands in a file, the shell history or chat; the bash `read -p` form does not work in
zsh, it hashes the empty string) and pasted only the hashes; **he chose one secret for both the word
and the password** (told him the link then carries the password; his call — it is a preview). Both
constants are filled in the commit; an empty hash would mean the switch does not exist. Told Shaka again: this
hides the preview from visitors, not from someone reading the public repo; a server-side gate
(the ptgcapi worker) would be the stronger option and was not chosen.

Tested in the harness with throwaway hashes (removed afterwards): wrong password → "No.", right
password → flag written, v2 on, still on after a reload, URL cleaned; a fresh navigation with the
word while the flag is on → "Turn off" clears it and the classic header returns.
